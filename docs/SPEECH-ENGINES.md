# موتورهای تشخیص گفتار: محدودیت‌های واقعی و انتخاب ما

این سند پاسخ مستقیم به این پرسش پروژه است: «آیا Web Speech API برای تشخیص چندزبانه هم‌زمان،
Code-Switching، دقت فارسی و اصطلاحات انگلیسی داخل فارسی کافی است؟»

## 1. محدودیت‌های تأییدشده Web Speech API

| محدودیت | جزئیات | تأثیر روی این پروژه | راهکار پیاده‌شده |
|---|---|---|---|
| `lang` برای هر جلسه ثابت است | تغییر زبان = ساخت/ری‌استارت یک `SpeechRecognition` جدید | در یک جمله نمی‌توان دو زبان داشت | تشخیص خودکار + سوییچ در مرز جمله؛ موتور Whisper؛ حالت دو موتوره |
| تشخیص چندزبانه هم‌زمان وجود ندارد | `langs` فقط در API آزمایشی «on-device» هست و در Chrome فقط این زبان‌ها را دارد: de, en, es, fr, hi, id, it, ja, ko, pl, pt, ru, th, tr, vi, zh | **فارسی در `langs` نیست** ⇒ حتی با API جدید هم نمی‌شود «فارسی + انگلیسی» را هم‌زمان روی دستگاه گرفت | `langs` به‌عنوان قابلیت اختیاری پرسیده می‌شود (`onDeviceStatus`) اما مسیر اصلی نیست |
| پردازش ابری | در Chrome صدا به سرویس Google می‌رود؛ نیازمند اینترنت | خطای `network` در قطعی | خطای قابل بازیابی + ری‌استارت خودکار + پیام کاربر |
| جلسه خودبه‌خود پایان می‌یابد | به‌ویژه پس از سکوت طولانی | از دست رفتن بقیه صحبت | `autoRestart` + Reconciler برای حذف تکرار متن پس از ری‌استارت |
| نتیجه‌ها تجمعی هستند | `interim` کل جمله تا آن لحظه را تکرار می‌کند | خطر تکرار متن در درج | نمایش interim فقط به‌عنوان پیش‌نمایش؛ فقط final درج می‌شود |
| تشخیص فارسی | کیفیت متغیر؛ **کلمات انگلیسی را با حروف فارسی می‌نویسد** و برعکس | «ری‌اکت»، «لاراول»، «ای پی آی» | واژه‌نامه معکوس + توکنایزر اسکریپت‌آگاه + قواعد محافظ ترکیب‌ها |
| در دسترس نبودن در همه مرورگرها | Firefox پشت flag، Safari متفاوت | UX ناسازگار | `probe()` در هر موتور و پیام `unsupported` با راهنمای Chrome 116+ |

نتیجه: Web Speech برای «تایپ سریع روزمره» عالی است (تأخیر تقریباً صفر، بدون هزینه)، اما برای
خواسته‌ی محوری این پروژه (حفظ زبان هر کلمه در گفتار مخلوط) **کافی نیست**. بنابراین معماری
موتور-محور طراحی شد تا بتوان موتور دقیق‌تر را بدون بازنویسی وصل کرد.

## 2. مقایسه موتورها

معیارها: دقت فارسی، پشتیبانی از گفتار مخلوط (کدسوییچینگ)، تأخیر، هزینه، حریم خصوصی، آفلاین،
سازگاری مرورگر.

| موتور | دقت فارسی | گفتار مخلوط (fa+en در یک جمله) | تأخیر | هزینه | حریم خصوصی | آفلاین | سازگاری | وضعیت در افزونه |
|---|---|---|---|---|---|---|---|---|
| **Chrome Web Speech (cloud)** | متوسط تا خوب | ❌ یک زبان در هر جلسه؛ کلمات انگلیسی را فارسی‌نویسی می‌کند | ~۰.۲–۰.۵ ثانیه (streaming) | رایگان (سهمیه Google) | صدا به Google می‌رود | ❌ | فقط Chromium | ✅ پیش‌فرض |
| **Web Speech + vocab + تشخیص زبان** | خوب | 🟡 بهبودیافته: زبان جلسه خودکار عوض می‌شود | همان | همان | همان | ❌ | فقط Chromium | ✅ پیش‌فرض (Auto) |
| **دو موتور Web Speech هم‌زمان** | خوب | 🟢 بهتر: دو فرضیه، داوری با نسبت اسکریپت + واژه‌های فنی | همان | همان ×۲ CPU/شبکه | همان (۲ برابر داده) | ❌ | فقط Chromium | ✅ آزمایشی |
| **Whisper (whisper-1 / large-v3) روی سرور خودتان** | بسیار خوب | ✅ **زبان هر کلمه حفظ می‌شود** (مدل چندزبانه با auto-detect) | ۰.۵–۳ ثانیه بر اساس اندازه مدل و سخت‌افزار (streaming نبودن ⇒ تأخیر قطعه‌ای) | هزینه سرور خودتان (خودمیزبان ≈ ۰) | فقط به سرور خودتان | ✅ اگر سرور محلی باشد | هر مرورگر (fetch) | ✅ فعال |
| **whisper.cpp / faster-whisper محلی** | بسیار خوب | ✅ | ۱–۳ ثانیه روی CPU معمولی، بهتر با GPU | رایگان | کامل محلی | ✅ | جدا از مرورگر | ✅ با همان موتور HTTP |
| **transformers.js Whisper در مرورگر (WebGPU)** | خوب (tiny/base) تا بسیار خوب (small) | ✅ | ۰.۵–۲ ثانیه با WebGPU؛ روی CPU کند | رایگان (یک‌بار دانلود مدل ۴۰–۶۰۰MB) | کامل محلی | ✅ | Chrome 113+ با WebGPU | 🚧 در دست توسعه (`localAiEngine.js`) |
| **سرویس‌های ابری تجاری (Azure/Deepgram/AssemblyAI/Gemini…)** | خوب تا بسیار خوب | ✅ در بعضی مدل‌ها | streaming | پرداخت به‌ازای مصرف | صدا به سرویس سوم می‌رود | ❌ | هر مرورگر | 🔌 از طریق همان موتور HTTP قابل اتصال* |

\* اگر سرویس، endpoint سازگار با OpenAI داشته باشد مستقیماً کار می‌کند؛ در غیر این صورت یک آداپتور
کوچک (مثل `httpWhisperEngine.js`) کافی است.

## 3. انتخاب پیشنهادی (بر اساس اولویت‌های پروژه)

۱. **دقت** → Whisper (large-v3 روی GPU یا small/turbo روی CPU).
۲. **قابلیت اطمینان** → Whisper با سرور محلی + موتور Web Speech به‌عنوان fallback.
۳. **عملکرد (تأخیر)** → Web Speech برای تایپ سریع روزمره.
۴. **حریم خصوصی** → سرور محلی Whisper یا (در آینده) مدل درون‌مرورگری.
۵. **نگهداشت‌پذیری** → هر سه از یک قرارداد `SpeechEngine` استفاده می‌کنند.

پیش‌فرض افزونه: **Auto-detect با Web Speech** (بدون نیاز به تنظیم، بلافاصله کار می‌کند) و برای
کاربری که گفتار مخلوط سنگین دارد، در تنظیمات → موتورها، **Whisper** را فعال می‌کند.

مثال راه‌اندازی سرور محلی سازگار با OpenAI:

```bash
# whisper.cpp (سرور سازگار)
./server -m models/ggml-large-v3.bin --port 8080

# یا faster-whisper / vLLM / هر سروری که /v1/audio/transcriptions دارد
```

در تنظیمات افزونه:
- Endpoint: `http://127.0.0.1:8080/v1/audio/transcriptions`
- Model: `whisper-1` (یا هر نامی که سرور می‌پذیرد)
- API Key: خالی (برای سرور محلی)

سرور محلی ⇒ صدا از دستگاه خارج نمی‌شود و محدودیت «یک زبان» هم وجود ندارد.

## 4. چرا «فقط regex و واژه‌نامه» کافی نیست — و چه کردیم

واژه‌نامه بدون معماری درست، فقط خرابکاری می‌کند (مثلاً `js` داخل `Next.js` را به `JavaScript` تبدیل
می‌کند). بنابراین فراتر از regex:

1. **توکنایزر script-aware** (کلمه/فاصله/نقطه‌گذاری + حفاظت ZWNJ).
2. **detect زبان در سطح جمله و در سطح بخش** (`detectSegments`) برای گزارش و سوییچ.
3. **واژه‌نامه ساخت‌یافته** با نوع `proper`/`generic` و نگاشت دوطرفه (فارسی ⇄ انگلیسی).
4. **جست‌وجوی چندکلمه‌ای** («نکست جی اس») + **تطبیق فازی محدود** («لارول» → Laravel).
5. **قواعد محافظ**: ترکیب‌های چسبیده (`Next.js`, `node.js`, `web-worker`) و URL/ایمیل هرگز لمس
   نمی‌شوند؛ واژه‌های عمومی فارسی‌شده به‌صورت پیش‌فرض فارسی می‌مانند.
6. **Sentinel برای خروجی کاربر**: قاعده‌ی کاربر همیشه بر واژه‌نامه داخلی اولویت دارد.
7. **محافظ عربی**: `ي/ك → ی/ک` فقط وقتی زبان فارسی تشخیص داده شود (متن عربی دست‌نخورده می‌ماند).

اما همین ماژول‌ها صریحاً «حل‌کننده» کدسوییچینگ نیستند؛ آن‌ها خطای نمایش را اصلاح می‌کنند، نه خطای
تشخیص را. تشخیص واقعی گفتار مخلوط فقط با یک مدل چندزبانه (Whisper) ممکن است — که در این معماری
به‌صورت یک موتور درجه‌یک پیاده‌سازی شده است.

## 5. نقشه راه موتور محلی (LocalAiEngine)

`src/engines/localAiEngine.js` قرارداد را پیاده کرده و دلیل «امکان‌پذیری» را برمی‌گرداند. برای
فعال‌سازی واقعی:

1. اجرای مدل در همان offscreen document (به میکروفون و WebGPU دسترسی دارد و از CSP صفحه آزاد است).
2. پنجره لغزان ۳۰ ثانیه‌ای با گام ۵ ثانیه + تقسیم‌بندی بر اساس VAD → پخش متن به‌صورت interim.
3. `language: null` در هر chunk ⇒ تشخیص خودکار زبان در سطح chunk (پایه کدسوییچینگ واقعی آفلاین).
4. `initial_prompt` از `buildVocabularyPrompt()` برای حفظ املای واژه‌های فنی.
5. دانلود مدل با رضایت صریح کاربر (۴۰–۶۰۰MB) و کش در Cache Storage.

با این کار هیچ فایلی جز `localAiEngine.js` و معرفی آن در `factory.js` تغییر نمی‌کند.
